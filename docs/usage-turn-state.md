# 使用日志 Turn-State 列

使用日志单独展示本次上游尝试首次返回的真实 `X-Codex-Turn-State` 的字符数，支持点击该列快速筛选，也支持通过下拉框和字符数输入框筛选。长度不代表状态等级或模型能力。

- `292 字符` 等正数：已获取上游真实值。悬停显示字符数以及可正常 Base64 解码时的字节数，例如 292 字符可能对应 217 字节。
- `未获取`：已检查上游响应，未取得该字段。
- `未记录`：历史日志或请求未执行采集，例如在取得上游响应前就失败。不能推断为上游未返回。

同时支持 HTTP 响应头和 WS 转换后的 SSE metadata 事件。只统计上游返回值，不统计客户端回传值、恢复的映射或签发的代号。映射保存失败时仍记录已经观察到的真实值长度。每次选号尝试独立记录，旧流的迟到事件不会污染新尝试。

日志写入两个可空整数 `turn_state_length`、`turn_state_decoded_bytes`，列表与导出共用筛选条件：`turn_state=received|missing|not_recorded`，以及精确匹配 `turn_state_length=N`。默认全部。筛选在数据库分页前进行，不逐条请求诊断详情，不扫描 JSON 提取字段，也不回填旧日志。

PostgreSQL 的长度/时间索引随现有后台索引任务在线创建；SQLite 沿用现有迁移机制。新增列不发起探测、不改变上游请求、响应时序或代号映射策略。
