# 当前对话模型不可用的提示

模型支持校验失败继续使用 HTTP 400 / `session_model_unavailable`，告知用户当前对话无法使用哪个模型，并引导切换其他可用模型或新建对话后重试。HTTP 标记 `X-Should-Retry: false`；已经开始的 SSE 以协议终态保留错误码和完整文案，WebSocket 错误事件也保留完整提示。关闭帧按 UTF-8 边界截断，避免长中文提示产生无效关闭原因。

`gpt-5.6-sol` 是原生 Codex 请求的首选建议；仅在当前绑定账号的明确模型列表、API Key 的模型/账号范围、网关模型映射、模型目录、冷却及会话容量检查通过时显示。无法核实则只说“其他可用模型”，不从别的账号复制推荐，也不改变会话绑定、切号或调度规则。推荐是当前配置下的可尝试选项，不保证外层网关权限和上游未来可用性。

容量不足且没有安全切换候选时，仍使用 `no_available_account`，提示“当前对话的处理容量暂时不足”，引导稍后手动重试。其他切换失败保留中性临时不可用提示，不宣称模型被关闭。

现有模型列表不能证明模型质量下降，因此不输出“降智”“质量异常”或“会损坏项目”。只有未来有明确质量停用原因时才能使用对应提示，不能从模型不支持或账号容量满推断。

用户提示不带上游账号、账号 ID、内部模型映射目标、会话/窗口 ID、切换代次。错误码和后台原有诊断仍保留，便于关联实际原因。用户请求的公开模型名可以回显。

NewAPI 的渠道级模型不匹配采用相同中性引导；转发 codex2api 的 400 错误时保留具体文案和不重试语义，Responses SSE 也原样传递 `response.failed` 中的提示。
