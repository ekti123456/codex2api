# 原生 Codex 响应标识隔离

核查日期：2026-09-18。范围是 codex2api 原生 Codex 账号的 Responses HTTP、SSE、原生 WS 和 compact 路径；API relay 的转发协议不在本次改写范围。核查使用本地代码及模拟上游，没有调用生产模型或读取生产数据库。

## 本次实现

### response.id / previous_response_id

- 向客户端返回 `resp_` 开头的随机代号，包含 128 位随机数和 128 位本地认证码；不编码原始 ID、账号编号、用户编号或创建时间。
- 数据库 `codex_response_ids` 保存加密后的原始 ID。代号绑定调用方、原始根会话、账号真实身份及切号代次。同一绑定下，同一原始 ID 复用代号；不同用户、根或账号不会共用代号。
- 映射保留 7 天，重启或共享同一数据库的多实例可以恢复。保存映射不代表上游响应仍在其缓存里，也不代表该响应已被客户端成功接收。
- 创建、进行中、完成、失败事件里的 `response.id`、协议级 `response_id` / `previous_response_id`，以及非流式 JSON/compact 的 `id` 均处理。不会递归替换生成文本、工具参数里的字符串。
- 客户端回传后，在读取本地续链缓存前先校验归属。通过后以代号查本地缓存、关联账号；只有确实需要把 `previous_response_id` 发往上游时，才在执行器边界还原原值。现有 HTTP 全历史展开及删除该字段的行为继续适用。
- 升级前的原始 ID 仅在现有 response-account 关联中能核实调用方、根、当前账号时兼容。切号后还须匹配出站代次。原有短期关联默认约 1 小时，未被记录或已经过期的旧 ID 不能因此被当作可信来源。
- 未知、过期、跨用户、跨根、账号身份变化及旧切号代次均拒绝续链。客户端统一收到 `previous_response_not_found` 和恢复完整历史的提示，不返回具体账号、查询命中细节或拒绝分支。
- 跨根的 fork 不能直接借用父根的响应代号续链；应携带完整 input。普通携带完整历史的 fork 不依赖此字段。
- 账号 A → B → A 不会重新接受 A 的旧代次代号。内部重试/执行器二次准备时允许已经还原的原值，但必须再次核对账号与代次。

管理员用量诊断和服务错误日志新增 `response_identity`，记录签发、兼容旧值、还原和拒绝。`alias` / `original` / `received` 可供核对；错误字符串中的响应 ID 被替换时，原始错误消息在 `original_error` 中保存。映射或存储异常不会退回原始 ID 下发。

### 事件内响应头

覆盖顶层 `headers`、`metadata.headers`、`response.headers`、`response.metadata.headers`，包括带前缀的 metadata 事件、其他事件和非流式 JSON。HTTP 外层原有选择性下发逻辑继续保留；不能把外层头过滤当成正文过滤。

允许的事件内头：

| 头 | 处理 |
| --- | --- |
| `X-Codex-Turn-State` | 使用现有持久化代号；缺少映射能力则删除，不透传原值 |
| `openai-model` / `x-openai-model` | 保留实际模型语义，不伪造模型 |
| `X-Reasoning-Included` | 保留统计语义 |
| 其余，包括 request/trace ID、组织/账号、cookie、配额、模型目录 ETag、未知扩展头 | 从上述头字典删除 |

头名不区分大小写；支持字符串/数组形式的 Turn-State，JSON 转义不绕过解析。正文里的安全审查、验证、缓冲控制以及模型、usage 保留。工具调用 ID、输入项 ID、密文、工具参数均未被这次改写。

SSE 每次处理一个事件，文本增量保持原样；每个请求对同一响应 ID 只首次访问签发表，后续事件使用内存映射。不会额外向官方发请求。JSON 转换延迟到正文读取阶段，不提前读取正文阻塞响应头；缺失或错误的 Content-Type 也不应绕过转换。数据库首次映射和入站校验有实际成本，不能称为零开销。

## 仍可能暴露账号关联特征的出口

以下是代码路径允许出现的内容，不表示本次生产日志已经实际包含这些字段。响应 ID、密文或 trace ID 通常不能直接解码成账号邮箱，但可成为跨记录关联的依据。

| 优先级 | 内容 / 当前状态 | 后续处理建议与限制 |
| --- | --- | --- |
| 高 | `codex.rate_limits` 的独立事件，及 JSON 额度错误中的 `plan_type`、`resets_at`、`resets_in_seconds`、精确 `Retry-After`。本次头字典过滤不会删除这些独立字段 | 对外只显示用户自己在网关的额度或通用暂不可用；真实上游额度留管理端。必须在内部调度/冷却采集之后处理，否则会破坏账号管理。不能伪造“还有额度” |
| 高 | HTTP/WS 错误消息、error details。可能引用组织/账号/邮箱/上游追踪 ID、套餐或重置时间 | 统一客户端错误出口：保留客户端能处理的错误码及修复参数提示，删除上游身份/路径细节；管理员保留完整原始错误。本次只处理其中的 response ID 引用，并非完整错误脱敏 |
| 高 | reasoning、compaction、内容块的 `encrypted_content`，以及 `encrypted_function_args` | 仍为原值，可能被保存并回传；不能断言其中一定包含账号，也不能保证跨账号必然可用或必然不可用。若要求原始不透明状态不出网关，需完整的认证封装、解包和来源检查，不能直接删除而损失上下文 |
| 中 | 输出项 `id`、事件 `item_id`、`call_id`、`item_reference.id` | 仍为原值；可以关联工具调用和历史。后续若改代号，必须同时处理 added/done/delta、最终 output、历史回传及工具结果配对；单改一端会导致工具丢失或孤立结果 |
| 中 | `conversation` / `conversation_id`，文件、容器、MCP 等资源引用、附件 URL | 需要按实际支持的功能绑定资源所有者并代理访问。普通引用网页 URL 不是账号凭证，不能一律替换。当前未证明生产用户出现了全部这些字段 |
| 中 | `internal_chat_message_metadata_passthrough`、响应 metadata 的非 headers 部分、SSE `id:` / 注释、未列出的扩展字段 | 并未建立全协议允许列表。有些内容由客户端本身生成，有些可能是上游关联信息；需区分来源。安全/审核控制不能为隐藏标识而整块删除 |
| 中 | NewAPI 的普通用户日志 | 当前 `formatUserLogs` 隐去 `admin_info` / `audit_info` 和频道名，但顶层 `upstream_request_id` 仍可见。它可能是 codex2api 的本地请求 ID，不一定是官方请求 ID；需要按实际来源核查，不能直接等同于账号泄漏 |
| 低/不可完全消除 | 实际模型、延迟、缓存命中、真实功能差异、工具结果中的业务数据 | 可被用于推测服务差异，但不构成账号身份证明。不能靠伪造模型、usage、时间或任意改写生成内容声称彻底隐藏账号 |

此外，现有 Turn-State 代号为了保持类似格式，保留了原始封装的公开版本、时间与长度形态；真实密文没有下发，但不能称为完全消除了统计特征。这次没有改变其既有生成规则。

## 已确认的保护及边界

- 原生 HTTP 主路径只选择性下发 Turn-State 和内部首响应头，不是复制所有上游 HTTP headers；不能据此误报 Authorization、cookie 或组织头已经普遍泄漏。
- NewAPI 会消费并移除窗口授权、调度诊断、内部首响应头；SSE 调度注释和 WS 私有调度 details 也有专门处理。直连 codex2api 与经过 NewAPI 的出口必须分别验收。
- 管理诊断包含原始状态和映射，属于敏感管理数据，不能把管理员日志接口或导出接口开放给普通用户。本项目诊断接口位于 admin 鉴权中间件之后。
- API relay 通道未套用本次原生账号响应 ID 改写，不能把此补丁宣称为所有供应商、所有协议的统一脱敏层。
- 用户保留一个合法代号，在外部请求后再带原来的代号回来，服务端无法仅凭相同输入证明其从未访问外部。代号能限制本地状态的恢复和关联范围，不能证明完整浏览/调用路径。

建议下一步优先统一独立额度事件和公开错误出口，再处理不透明上下文与工具引用。扩大隔离前应明确历史兼容策略，验证工具配对、压缩缓存、切号、HTTP/WS 转换及资源获取，避免再次造成工具或历史丢失。

## 验证范围

专项测试覆盖持久化和过期、共享数据库并发签发、不同密钥与共享缓存、跨用户/根、切号及 A→B→A、可验证旧 ID、未知引用、HTTP/SSE/WS/compact、工具字段保持、缺失 Content-Type 和延迟读取。错误消息中的未知响应 ID 不会获得可续链代号。前端完成 TypeScript 检查和构建。均为本地模拟测试，未部署或执行生产模型请求。
