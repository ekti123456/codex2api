# 主会话连续性与原账号保护

管理员入口：提示词防护 → 风险控制 → **会话连续性校验（测试）**。保存后生效，旧配置默认 `observe`。

## 测试模式

- `off`：不按窗口序号判断或拦截；仍维护原账号与可解析的序号基线。
- `observe`：记录 `would_block` 与原因，但不因序号异常拦截。建议先运行此模式，检查使用统计中的请求诊断。
- `enforce`：按以下规则拒绝异常主请求，HTTP 返回 400，WS 返回对应错误帧。开启前需在管理界面再次确认。

该模式不关闭身份签名验证、原账号保护、模型限制或收费授权。身份/账号归属冲突、无法安全读取归属、原账号容量不足仍会停止请求，不能通过切换观察模式绕过。

| 已记录状态 → 当前主请求 | 处理 |
| --- | --- |
| 无归属 → `T:0` | 允许首次选号，准入后保存归属 |
| 无归属 → `T:11` | `unbound_nonzero`；观察模式仅记录，正式模式拒绝 |
| 有归属但无序号记录 → `T:71` | 首次建立基线，继续原账号，不把旧窗口当作新窗口 |
| `T:71` → 主请求/压缩 `T:71` | 复用原账号 |
| `T:71` → 主请求 `T:72` | 正常推进，不创建新账号绑定 |
| 跳号、回退、线程不一致 | 记录具体原因；仅正式模式按序号拒绝 |
| 缺失或矛盾的窗口字段 | 不假定为 0，不用矛盾值推进基线 |

解析原始请求的 `thread_id:window_number`，并核对元数据中的 `window_number`（如果存在）。WS 只使用当前帧字段，不拿升级握手或上一次帧的窗口序号补空。不改变发往上游的既有字段收敛、时区改写和签名处理。

压缩请求使用它携带的当前序号，不在压缩开始时预增。基线记录“已准入的最高有效序号”，不是直接用最后完成的请求覆盖：较旧请求晚结束不会回退基线。序号表示客户端上下文的推进线索，不是用户消息轮数；非零本身也不能证明请求来自旧设备或伪造客户端。参考 [官方 Codex 仓库](https://github.com/openai/codex)。

## 保号与扩容

仅针对已识别为 `thread_source=user` 的稳定主链路（包括拥有主根的压缩请求）维护持久归属。后台关联与等待策略不在本次扩大调整。

账号会话槽闲置释放与账号归属分离：释放槽不等于遗忘原账号。主请求在启动/重连后可从持久记录或已确认窗口授权恢复原账号。候选重试、压缩偏好、fork 继承均不能越过已恢复的原账号；不支持所选模型仍提示新开对话，不改投其他账号。

这是持久硬绑定，不是提高调度权重。已保存的根账号归属不设 TTL，不因间隔两小时、计费窗口到期、模型切换或进程重启重新选号；序号测试模式为 `off` 或 `observe` 时也不解除账号归属。原账号支持新模型时仍用原账号，不支持则返回 `session_model_unavailable`；账号不可用时停止请求而不是自动换号。上述保证依赖同一根身份和归属数据仍然存在：旧版本已经丢失或改写的历史归属不会从使用日志自动重建，新开对话才按首次选号规则处理。

普通槽不足时，未授权扩容的已有普通窗口返回 `codex_sticky_expansion_required`；普通和保留槽均满返回 `codex_sticky_account_capacity_full`。同账号并发、暂停、额度、模型等限制仍生效，保留槽不绕过这些约束。

NewAPI 的个人窗口页提供单窗口确认：先开启扩容，再确认该窗口后续请求的新倍率。控制端只信任经签名的用户身份和管理员策略，不接受客户端指定上游账号。预占原账号保留槽，提交新价格版本后才能放行；失败回滚临时占位。保留原创建时间和到期时间，占一份个人扩容额度，历史与已授权在途请求不追溯加价。旧价格授权再次使用会返回 `window_billing_refresh_required`，由 NewAPI 在转发前重新授权和重算预扣。

## 诊断与性能

使用统计 → 请求诊断 → 会话连续性校验，包含 `mode`、`result`、`action`、`would_block`、原始 `thread_id`、前后序号、原账号及归属来源。拒绝在选号前发生时也记录诊断。

新增 `codex_session_continuity` 表按根键精确读写，不扫描历史用量。首次绑定或有效序号推进持久化；普通同序号请求命中内存，活跃时间写入最多每根 5 分钟一次。归属缓存和价格缓存各限制 32768 项。窗口列表仍按用户查询，并使用 NewAPI 原有短缓存与合并查询；单窗口升级只在用户确认时请求控制端。持久归属不随槽位 TTL 删除，存储随历史根数增长；运维清理该表会失去对应根的重启恢复能力。

先部署 Codex2API，再部署 NewAPI。仍需保证同一上游账号由同一调度进程管理或使用粘性路由；本功能不是跨独立调度器的分布式账号锁，也不承诺跨独立进程的即时价格缓存同步。回滚旧 Codex2API 前先停止单窗口升级入口并排空旧价格授权，避免旧版本不识别升级后的价格版本。

回归覆盖：三种模式、配置保存、HTTP/WS 非零初始窗口拦截、旧握手与当前帧分离、`71 → 压缩71 → 72`、缺字段基线、重启恢复、禁止改投其他账号、扩容额度与保留位不足、占位失败回滚、旧价格票刷新和在途价格快照。
