# 用户窗口动态策略

位置：提示词防护配置 → 用户 / IP / 会话风险审计 → 限制用户新建会话数量下方。

动态间隔与风险评分、窗口数量限制的开关独立。默认关闭；可选择「仅观察」或「正式限制」，保存配置后生效并持久化。参数恢复默认不会改变当前模式。

每个档位还支持 `window_limit_delta`（用户窗口数量调整），旧配置缺省、新增档位和恢复默认都为 0。按用户当前普通窗口上限加减：基础为 5 时，`1` 得到 6，`-1` 得到 4，`0` 仍为 5；最低 1，最高 100000。用户单独配置的数量作为基础值，「不限制」豁免；全局数量限制未开启且无用户单独限制时不调整。只改普通窗口上限，不修改额外扩容名额、已确认窗口的倍率，也不关闭已有窗口。

数量调整与创建间隔使用同一批有效周期、同一个平均用时档位和最少样本要求，但数量调整不需要先达到近期创建频率。关闭时不调整，观察模式只记录建议数量，正式限制时实际生效；统计失败或样本不足仍使用基础上限。界面窗口上限、扩容报价与请求准入使用同一算法。

## 默认规则

- 过去 30 分钟已有 2 个成功创建的不同根窗口，第 3 个开始检查。
- 最近 7 天至少 10 个符合条件的账号使用周期，取最新 20 个计算平均值。
- 周期沿用账号窗口口径：首次占用到最后一次请求结束；闲置释放后重新占用是另一个周期。
- 平均用时 ≥15 分钟：不增加间隔；≥10 且 <15 分钟：5 分钟；≥5 且 <10 分钟：10 分钟；<5 分钟：15 分钟。
- 默认间隔上限为 15 分钟。

「间隔」从上一个成功窗口的创建时刻起算，不是每次请求再等一次。平均用时正好 5 分钟时匹配 10 分钟档位。若 12:00、12:05 创建两个窗口，12:06 请求第三个，预计 12:15 可创建；重复请求不会推迟这个时刻。若频率统计范围先移出旧创建记录，使频率条件不再满足，则提前解除动态间隔。

## 可配置项

高级配置路径为 `risk.session_creation_cooldown`：

| 字段 | 默认值 | 可配置范围 |
| --- | --- | --- |
| `mode` | `off` | `off` / `observe` / `enforce` |
| `frequency_window_seconds` | 1800 | 60～86400 秒 |
| `free_creations` | 2 | 1～1000 |
| `history_days` | 7 | 1～90 天 |
| `min_samples` | 10 | 1～200，不得大于最大样本数 |
| `max_samples` | 20 | 最小样本数～200 |
| `max_interval_seconds` | 900 | 0～86400 秒 |
| `tiers` | 四个默认档位 | 1～12 个，下限不可重复，必须包含下限 0 |

档位使用 `min_average_seconds`、`interval_seconds` 和 `window_limit_delta`；按最大的已满足下限匹配，下限包含边界。下限最多 30 天，间隔最多 24 小时；最终间隔受 `max_interval_seconds` 限制。界面按分钟编辑，API 按整数秒配置。间隔 0 表示不增加 CD；数量调整为 -100000～100000 的整数，0 表示上限不变。

## 身份、计数与失败处理

- 仅使用已验证 NewAPI 平台与用户身份，不信任调用者自行填写的用户信息。同一平台用户跨 API Key、跨账号共享状态，不同平台隔离。
- 仅在调度账号启用了账号窗口控制时执行请求准入。用户级「不限制」覆盖同时豁免动态策略；「单独配置」覆盖基础窗口数量和统计范围，数量调整在此基础上计算。
- 已有根窗口、仍在占用账号窗口的会话、复用根的审查 / 标题 / 子代理、压缩不增加 CD；无可信稳定身份不强制执行。
- 新创建先预留名额，HTTP 请求 / WS 当前轮结束后，根据成功用量结果确认。并发处理中暂按预留名额判断，避免同时请求绕过；同根并发共用创建记录。
- 纯失败请求退出时撤销预留；没有其他成功或在途请求时，同时撤销本次新增的用户窗口占位。已有的旧窗口不回滚。
- 每次重试复用原预留，不延长创建时刻。WS 每轮退出清理本轮凭据，下一帧重新判断。
- 数据库存储创建状态，事务串行化同一用户的变更；重启不清除成功创建记录。进程异常退出的在途预留最多残留约 2 分钟，正常请求期间每 30 秒续租。

## 样本与兼容性

限流平均值单独查询，不改变画像页面原有累计平均值。只有包含正常成功结果且已超过账号闲置到期时间的周期，才可能成为样本；本机仍处于占用状态的周期再次排除。纯失败、仍在使用、缺少成功证据的历史周期不计入。为防止把故障恢复前的短时数据用于加严，提前手动释放的周期也保守地等到所记录的闲置到期时间后才入样。

成功证据从安装本版本开始记录（功能关闭也会积累），不推测或回填旧数据。初次启用可能需要积累最少样本；原有数量限制在此期间仍有效。没有样本或数据库查询失败时跳过动态加严，并记录后台诊断，不把统计故障变成用户无法使用。

正式限制返回 HTTP 400，沿用 `session_creation_limit_exceeded`，提示具体 UTC 恢复时间及剩余时长，携带 `Retry-After`。现有 NewAPI 已将此错误视作不重试的窗口限制，并排除在可用率 / 错误桶统计之外，无需新增 NewAPI 错误类型。最终是否重试仍由请求客户端决定。

若窗口数量与动态间隔同时限制，使用两者恢复时间的较晚者，不相加。观察模式仅在后台输出 `event=session_creation_cooldown mode=observe`，包含脱敏主体 / 根标识、平均用时、样本数、近期创建数、间隔和恢复时刻，不记录正文或认证信息。它不会新增拦截，也不会取消原有数量限制。

数量观察使用 `event=session_window_adjustment mode=observe`，记录脱敏主体、平均时长、样本数、基础及建议上限。同一 HTTP 请求或 WS 轮次的数量和间隔判断复用一次有界样本查询；WS 轮次结束清理快照，避免下一轮沿用旧统计。全部档位的数量调整为 0 时不增加统计查询。
