# 会话过载 500 统计与永久黑名单

侧边栏新增「会话过载统计」，页面 `/admin/session-errors`。仅统计升级后最终 **500 + `server_is_overloaded`**，例如 `server_is_overloaded · service_unavailable_error · Our servers are currently overloaded...`。不包含其他 500、`slow_down`、仅文案含 overloaded 的错误，或 429、502、503；这些仍保留在原错误日志中。按准确错误码识别，不按 `error_kind=server` 或全文模糊匹配。

HTTP 标准错误与原始错误响应、SSE 的最终失败、Responses WS 每个逻辑回合均按请求去重。流式以最终用量记录中的逻辑状态为准，不把 HTTP 200 握手当成成功；同类上游 500 为停止客户端重试而映射为 400 时也保留统计。`is_retry_attempt=true` 的中间失败不计数，内部失败后重试成功也不增加计数。新增统计不会自动锁定，只有管理员确认批量锁定才加入黑名单。

## 身份与粘性

NewAPI 根指纹本来就由 `平台 + 用户 ID + 主 session_id` 生成，不包含模型、设备 ID 或 `window_id` 的序号。本次增加签名的 `root_session_id`，Codex2API 验证它与根指纹一致后用于展示；不改旧指纹/账号绑定键，不把标题或子代理自己的 session_id 直接拼入主根粘性，避免拆分附属请求与已有窗口。

统计和黑名单使用独立的完整 SHA-256 主体/会话键。NewAPI 主体来自有效签名的用户与平台，不使用客户端自报用户；同一用户换 Token 不解除黑名单。直连请求以已鉴权 API Key 为主体，不跨用户/平台合并同名会话。旧 NewAPI 没有新字段时，只在原始会话与根指纹一致时显示原始 ID，否则展示根指纹，不猜测。没有稳定身份的错误仍留在已有错误日志，不强行归到某个用户。

主账号的持久归属仍不设 TTL：额度耗尽、禁用、暂停、冷却、缺凭证、换模型、请求重试排除均不能改投其他账号。模型不支持时提示新开对话；容量不足按单窗口扩容确认规则处理。黑名单也不解除原账号归属。

## 锁定与 fork

管理员可以多选当前页会话，一次确认后加入长期黑名单；没有自动到期时间，仅手动解锁。只影响列出的用户与会话，不禁用整个用户，不取消已准入的在途请求。黑名单页面独立展示已锁会话，即使错误统计已经清理也可以解锁。

锁定后返回 400 `session_blacklisted`、中文说明及停止重试提示。主会话、归并到主根的子代理、携带已验证 fork 关系的派生会话都会被拒绝。已观察到的 fork 父链独立持久化，后续不再携带父字段或进程重启也不能解除继承锁定；多级 fork 向上检查，最多 64 级，循环/过深/父关系冲突时拒绝而非绕过。新的父关系会清除原来的放行缓存。

**代理无法禁止客户端本地创建一个空 fork，也无法证明一个完全改换 ID 且移除全部父关系的新请求是从哪个会话复制的。** 不使用提示词相似度、设备 ID 或时间接近来猜父会话，以免误锁其他正常对话。黑名单只承诺拦截代理可识别的会话及派生调用，不是客户端本地操作权限控制。

## 性能与保留

- 每会话一行增量统计，不扫描历史用量 JSON。计数为当前保留记录的累计值，不是最近某段时间的错误率。无新错误的记录保留 7 天，后台约束约 10 万条；仅保留最近一次错误摘要。
- 独立有界队列 512 条，单协程每秒或每 64 条批量写入。请求不等待统计数据库；饱和/失败丢弃计数可见，不无界排队。正常退出最多等待 3 秒排空，异常退出可能丢失尚未写入的统计。
- 会话/用户精确查询、游标分页；黑名单状态按页批量查询，不逐行查数据库。管理查询与批量修改各限时 3 秒，每批最多 100 个会话，非法/不存在项导致整批回滚。
- 黑名单热路径为最多 4096 项、2 秒 TTL 的本地缓存；冷查询按主键及有界父链查找，不扫描全表。同进程锁定/解锁立即清缓存；共用数据库的其他进程最多约 2 秒后重新检查。存储故障拒绝已识别会话，不转发到其他账号。
- 黑名单、父链和永久账号归属不随统计保留期清理；其存储随历史锁定会话及已知 fork 数量增长。不同独立数据库/服务池之间不自动同步。
- 页面只在首页可见、没有选中会话或确认中的操作时每 30 秒刷新，历史分页不轮询；切换筛选取消旧请求并清空选择。

## 接口

- `GET /api/admin/session-errors`：`user_id`、`session_id` 精确筛选，`locked=true` 查看直接黑名单，`cursor`、`limit`（1–100）。返回分组、累计 500 数、最新错误与采集器状态。
- `POST /api/admin/session-errors/blacklist`：`{"keys":["服务端返回的会话键"],"locked":true}`；`false` 表示手动解锁。使用既有管理员鉴权。继承锁定需要解锁其父黑名单，不能只解除子会话来绕过。

建议先部署 Codex2API，再部署带新签名字段的 NewAPI；历史日志不能补出从未采集的身份或父链。
